# RP2040 & RP2350 Engineering Reference (Raspberry Pi Pico / Pico 2)

Load this reference when developing C/C++ firmware with the Raspberry Pi Pico SDK on RP2040 or RP2350 (Pico, Pico W, Pico 2, Pico 2 W).

## Hardware & Architecture Differences

| Topic | RP2040 (Pico / Pico W) | RP2350A / RP2350B (Pico 2) |
| :--- | :--- | :--- |
| **Cores** | Dual ARM Cortex-M0+ (133 MHz, no FPU) | Dual ARM Cortex-M33 (FPU/DSP) **or** Hazard3 RISC-V (150 MHz) |
| **SRAM** | 264 KB (striped across 6 banks) | 520 KB |
| **PIO Blocks** | 2 PIO blocks (8 state machines total) | 3 PIO blocks (12 state machines total) |
| **ADC Pins** | `GPIO26–29` (4 ch; `GPIO29` = VSYS/3 on Pico) | RP2350A: `GPIO26–29` (4 ch); RP2350B: `GPIO40–47` (8 ch) |
| **Logic Voltage** | **3.3 V only (NOT 5 V tolerant)** | **3.3 V only** (5 V tolerant only when IOVDD = 3.3 V in specific conditions — check datasheet & errata; treat as 3.3 V by default) |

## Top RP2040 / RP2350 Firmware Pitfalls
1. **XIP Flash Stall During Flash Erase / Program**:
   - Code normally executes directly from external QSPI Flash (XIP). Writing/erasing Flash disables XIP!
   - Both cores MUST stop executing from Flash during `flash_range_erase()` / `flash_range_program()`:
     - Disable interrupts (`save_and_disable_interrupts()`),
     - Lock out Core 1 via `multicore_lockout_start_blocking()` (if Core 1 is running), or use `flash_safe_execute()` in modern Pico SDK,
     - Mark any latency-critical ISR that must stay alive with `__not_in_flash_func(fn)`.
2. **Pico vs Pico W / Pico 2 W LED & Pin Differences**:
   - Standard Pico routes the LED to `GPIO25`.
   - **Pico W / Pico 2 W** routes the LED through the CYW43439 wireless chip (`cyw43_arch_gpio_put(CYW43_WL_GPIO_LED_PIN, 1)`), and `GPIO23/24/25/29` are used internally by the wireless interface!
3. **Dual-Core Synchronization**:
   - Never assume `volatile` alone synchronizes Core 0 and Core 1 safely for multi-step operations. Use Pico SDK `mutex_t`, `queue_t`, hardware `spin_lock_t`, or `critical_section_t` (which disables interrupts AND claims a spinlock).
   - Avoid using the raw SIO inter-core FIFO (`multicore_fifo_*`) if you also use `multicore_lockout` or `flash_safe_execute`, because lockout uses the SIO FIFO internally!
4. **RP2040 ADC Errata & Noise**:
   - RP2040 ADC has DNL spikes at specific codes (512, 1536, 2560, 3584) and shares power noise from the SMPS (`GPIO23` PWM mode reduces ripple at the cost of idle current). Filter `ADC_VREF` carefully for precision readings.
5. **RP2350 Erratum E9 (GPIO Pull-Down Latching)**:
   - On RP2350 A2 silicon, internal pull-downs can latch high if an external signal drives ~2 V into an input with IE enabled. Use stronger external pull-downs (<= 8.2 kOhm) or disable input buffer (`gpio_set_input_enabled(pin, false)`) when idle on affected designs.
6. **PIO & DMA Best Practices**:
   - Check PIO instruction budget (max 32 instructions shared per PIO block) and always release/claim state machines dynamically (`pio_claim_unused_sm`) instead of hardcoding `pio0, sm0` in reusable libraries.
